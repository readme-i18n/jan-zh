# Bitdefender 误报事件

针对2024年1月10日Jan 0.4.4版本在Windows平台触发Bitdefender误报Gen:Variant.Tedy.258323病毒的事件，我们现提供完整的事后分析报告并概述后续应对措施。

## 事件概述

### 问题描述

Jan 0.4.4在Windows平台安装时触发Bitdefender将其误判为感染Gen:Variant.Tedy.258323病毒，导致程序被自动隔离。

### 受影响的杀毒软件

- McAfee / Microsoft Defender 未受影响
- Bitdefender 持续触发误报

### 事件时间线

- _1月10日 凌晨2:18 新加坡时间:_ Hawke报告Windows电脑安装0.4.4版本时触发恶意软件杀毒软件报错
- _1月10日 凌晨2:21 新加坡时间:_ @0xSage在Discord作出回应
- _1月10日 凌晨2:35 新加坡时间:_ Hawke确认多人在全新安装时遭遇此错误
- _1月10日 凌晨2:41 新加坡时间:_ @louis-jan和@dan-jan出于谨慎考虑回退0.4.4版本
- _事件持续中:_ 次日将进行问题分类调查
- _1月10日 上午11:36 新加坡时间:_ @Hien检查了所有Nitro版本并使用Bitdefender扫描。仅最近两个版本触发警告(0.2.7, 0.2.8)
- _1月10日 中午12:44 新加坡时间:_ @Hien重新测试0.2.6版本，建议暂时使用0.2.6，剩余两个Nitro版本(0.2.7, 0.2.8)将进行深入调查
- 团队开始测试修复后的构建版本
- _1月10日 下午3:22 新加坡时间:_ 诊断发现很可能是误报。@Hien仅通过在GitHub托管运行器上构建Nitro Windows CPU找到解决方案，尚未确定根本原因
- _1月10日 下午5:24 新加坡时间:_ @Hien正在测试两种场景，仍试图理解Bitdefender的工作原理
- _1月11日 下午5:46 新加坡时间:_ 召开事后分析会议

## 调查更新

- @Hien 已调查所有 Nitro 版本并使用 Bitdefender 进行扫描，仅最新的两个版本触发了 Bitdefender 警告。重新测试了无此问题的最高版本 Nitro 0.2.6，确认不再触发 Bitdefender 警告。
- 我们观察到 Nitro 0.2.6 及以下版本不受影响，但 Bitdefender 将 0.2.7 和 0.2.8 版本标记为感染并删除。为推进当前发布，Hien 建议降级至 Nitro 0.2.6 版本进行测试，同时他将调查 Bitdefender 标记 0.2.7 和 0.2.8 版本的原因。
- 需要强调的是，0.2.6、0.2.7 和 0.2.8 版本间仅进行了微小改动，这些变更不应触发恶意代码警告。我们可以参考 0.2.7 和 0.2.8 版本的变更日志来定位具体改动。
- 核心信息是：我们未在 Jan 中引入恶意代码（属误报），调查旨在查明 Bitdefender 标记 0.2.7 和 0.2.8 版本的根本原因。
- 当前诊断显示为误报，但仍在调查中。参考链接：[此处](https://stackoverflow.com/questions/75886428/fake-positive-bit-defender-problem-genvariant-tedy-304469)、[此处](https://stackoverflow.com/questions/58010466/bitdefender-detects-my-console-application-as-genvariant-ursu-56053) 及 [此处](https://www.cisa.gov/sites/default/files/2023-06/mar-10365227.r1.v1.clear_.pdf)。
- @Hien 正在测试两种场景以理解 Bitdefender 工作机制，调查仍在进行：问题出在代码还是 CI？
  - 场景1：对 0.2.6 和 0.2.8 标签使用相同 CI 代理，在 Alan 和我的 PR 后，Bitdefender 标记了 Nitro CPU 二进制构建。表面看似乎是代码问题。
  - 但进一步实验发现：对 0.2.8 代码改用 GitHub 托管代理时，Bitdefender 未标记我们的二进制构建。
- 现已确认 Bitdefender 警告并非攻击事件，不存在恶意代码。
- 我们已定位事件源于某个 CI 代理，导致 BitDefender 误报警报。

## 经验总结

1. **杀毒软件兼容性认知:**

- _现象:_ 本次事件突显了识别和测试杀毒软件兼容性的重要性，特别是与 Bitdefender 等广泛使用的解决方案。
  - _经验总结:_ 未来我们将把各类杀毒软件（包括杀毒和"恶意代码检测"功能）的兼容性检查整合到 CI 或 QA 检查清单中。这项预防性措施旨在最小化发布和测试过程中的误报检测。

2. **跨平台测试:**

- **观察现象**：该问题未在 MacOS 和 Linux 系统上出现，表明我们在发布流程中的跨平台测试可能存在疏漏。
  - **经验总结**：需要澄清的是，这一现象与杀毒软件测试无直接关联。它更凸显了改进测试规程的必要性，需涵盖多操作系统环境。通过全面评估不同平台（考虑各类杀毒软件及 Mac/Linux 系统架构差异）的潜在问题，实现更完善的测试覆盖。

3. **用户沟通与文档记录**：

- **观察现象**：由于 Nicole 在凌晨 2 点仍活跃于 Discord 和 Github 并及时响应，这种快速反馈使我们能够准确评估影响范围。
  - **经验总结**：虽然本次用户沟通效果良好，但这主要依赖于 Nicole 在事件期间的实时响应。为提升整体响应能力，我们应优先建立"7×24 小时快速分类响应"机制，通过确保持续在岗或建立可靠的团队成员轮值制度，实现更迅捷的用户沟通与问题记录，从而进一步提升事件响应效率。

4. **主动式事件响应**：

- **观察发现**：虽然事件响应及时进行了版本回滚，但由于发布时间在午夜，导致响应略有延迟。这一延迟使得调查工作推迟至次日工作时间才开始。
  - **经验总结**：我们认识到快速事件响应在时效性场景中的重要性，特别是在非工作时间发布更新会影响响应速度。未来我们将优化发布时间安排，尽可能减少延迟，确保无论何时都能立即启动调查。这可能包括考虑调整发布时间窗口，或针对关键事件实施自动化响应机制，以实现更主动及时的解决方案。

5. **供应链安全措施：**

- **观察发现**：虽然该事件引发了我们对潜在供应链攻击的考量，但必须明确指出实际情况并非如此。不过，此次事件凸显了重新审视供应链安全措施的重要性。
  - **经验总结**：未来我们应通过引入额外的验证步骤来强化供应链安全，以保障发布流程的完整性。与分发渠道合作对于加强安全检查、构建更健壮的供应链至关重要。
  - **长期规划**：应考虑探索检测Jan恶意代码的方案，并将杀毒扫描纳入CI/CD流水线，以采取更全面、更主动的安全防护措施。

6. **用户误报教育**：

- **观察发现**：用户反馈Bitdefender会自动"清除"被标记的Nitro版本，未提供任何用户操作选项。
  - **经验总结**：需教育用户了解误报可能性，并指导他们如何将此类文件加入白名单或向杀毒软件供应商报告（如可行）。应明确告知用户在此类情况下的应对步骤。

这些经验教训将成为我们优化流程的基础，助力构建更具韧性的版本发布与事件响应机制。持续改进是维护软件可靠性与安全性的关键。

感谢您对此事的及时解决所付出的努力与合作。
