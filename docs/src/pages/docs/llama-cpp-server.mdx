# 本地 AI 引擎 (llama.cpp)

`llama.cpp` 是 Jan 用于在本地计算机上运行 AI 模型的核心**推理引擎**。本节涵盖引擎本身的设置，这些设置控制模型在您硬件上的*信息处理方式*。

<Callout>
寻找 API 服务器设置（如端口、主机、CORS）？它们已移至专门的 [**本地 API 服务器**](/docs/local-server/api-server) 页面。
</Callout>

## 访问引擎设置

在 **设置** (<Settings width={16} height={16} style={{display:"inline"}}/>) > **本地引擎** > **llama.cpp** 中找到 llama.cpp 设置：

![llama.cpp](./_assets/llama.cpp-01-updated.png)

<Callout type="info">
大多数用户无需更改这些设置。Jan 会自动为您的硬件选择良好的默认值。
</Callout>

## 何时调整设置

在以下情况下您可能需要修改这些设置：

- 模型加载缓慢或无法工作
- 您安装了新硬件（如显卡）
- 您希望针对特定设置优化性能

## 引擎管理

| 功能 | 作用 | 使用场景 |
|---------|-------------|------------------|
| **Engine Version** | 显示当前 llama.cpp 版本 | 检查与新模型的兼容性 |
| **Check Updates** | 下载引擎更新 | 当新模型需要更新引擎时 |
| **Backend Selection** | 选择硬件优化版本 | 硬件变更或出现性能问题时 |

## 性能设置

| 设置项 | 作用 | 推荐值 | 影响 |
|---------|-------------|-------------|---------|
| **Continuous Batching** | 同时处理多个请求 | 启用 | 使用工具或多聊天时速度更快 |
| **Parallel Operations** | 并发请求数量 | 4 | 数值越高=多任务能力越强，内存占用越大 |
| **CPU Threads** | 使用的处理器核心数 | 自动 | 更多线程可加速 CPU 处理 |

## 内存设置

| 设置项 | 功能说明 | 推荐配置 | 调整时机 |
|---------|-------------|-------------|----------------|
| **Flash Attention** | 高效内存利用 | 启用 | 除非出现问题否则保持启用 |
| **Caching** | 记忆近期对话 | 启用 | 加速后续问题响应 |
| **KV Cache 类型** | 内存与质量权衡 | f16 | 内存不足时切换为 q8_0 |
| **mmap** | 高效模型加载 | 启用 | 处理大型模型时有效 |
| **Context Shift** | 处理超长对话 | 禁用 | 超长会话时启用 |

### 内存选项详解

- **f16**: 最佳质量，占用更多内存
- **q8_0**: 内存与质量平衡
- **q4_0**: 最小内存占用，质量略有下降

## 快速故障排除

**模型无法加载：**

- 尝试更换后端引擎
- 检查可用 RAM/VRAM
- 更新引擎版本

**性能缓慢：**

- 确认 GPU 加速已启用
- 关闭内存密集型应用
- 增加模型设置中的 GPU 层数

**内存不足：**

- 将 KV Cache 类型改为 q8_0
- 减少模型设置中的上下文长度
- 尝试更小规模的模型

**崩溃或报错：**

- 切换至更稳定的后端（使用 avx 替代 avx2）
- 更新显卡驱动
- 检查系统温度

## 快速配置指南

**多数用户：**

1. 使用默认设置
2. 仅在出现问题时调整

**NVIDIA GPU 用户：**

1. 下载 CUDA 后端
2. 确保 GPU 层数设置较高
3. 启用 Flash Attention

**性能优化：**

1. 启用连续批处理
2. 根据硬件选择合适后端
3. 监控内存使用情况

<Callout type="info">
默认设置适用于大多数硬件。仅在遇到特定问题或需要针对当前配置优化时调整这些参数。
</Callout>
