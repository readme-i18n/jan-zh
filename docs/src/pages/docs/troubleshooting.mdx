# 故障排除

## 如何获取错误日志

错误日志对于排查问题和获取 Jan 团队帮助至关重要。获取 Jan 错误日志的步骤如下：

#### 通过 Jan 界面

1. 打开底部的 **System Monitor**
2. 选择 **App Log**

<br/>

![应用日志](./_assets/trouble-shooting-02.png)

<br/>

#### 通过终端

**应用日志**

```bash
tail -n 50 ~/Library/Application\ Support/Jan/data/logs/app.log
```

**服务器日志**

```bash
tail -n 50 ~/Library/Application\ Support/Jan/data/logs/cortex.log
```

<Callout type="warning">
分享日志或错误详情时，请确保删除任何私人或敏感信息。我们仅保留您的日志24小时。
</Callout>

## 构建损坏

解决 Jan 安装后卡在损坏构建状态的问题：

<Tabs items={['Mac', 'Windows', 'Linux']}>
  <Tabs.Tab>

      2. **Delete** Application Data, Cache, and User Data:

      ```zsh
      rm -rf ~/Library/Application\ Support/Jan
      ```

      3. If you are using a version before `0.4.2`, you need to run the following commands:

      ```zsh
      ps aux | grep nitro
      # Looks for processes like `nitro` and `nitro_arm_64`, and kill them one by one by process ID
      kill -9 <PID>
      ```

      4. **Download** the [latest version of Jan](/download)
  </Tabs.Tab>

  <Tabs.Tab>

      2. **Delete** Application Data, Cache, and User Data:

      ```cmd
      cd C:\Users\%USERNAME%\AppData\Roaming
      ```

## NVIDIA GPU 故障排查

解决 Jan 在 Windows 和 Linux 系统上无法调用 NVIDIA GPU 的问题。

<Steps>

### 步骤 1：验证硬件与系统要求

#### 1.1. 检查 GPU 识别状态
首先确认系统能识别 NVIDIA GPU：
**Windows：**
- 右键桌面 → NVIDIA 控制面板
- 或通过设备管理器 → 显示适配器查看
**Linux：**
```
lspci | grep -i nvidia
```
#### 1.2. 安装必要组件
**NVIDIA 驱动：**
1. 为您的 GPU 安装 [NVIDIA Driver](https://www.nvidia.com/en-us/drivers/)（需 **470.63.01 或更高版本**）
2. 验证安装：

```
nvidia-smi
```
正常输出应显示 GPU 型号和驱动版本。

**CUDA 工具包：**
1. 下载安装 [CUDA toolkit](https://developer.nvidia.com/cuda-downloads)（需 **CUDA 11.7 或更高版本**）
2. 验证安装：

```
nvcc --version
```
**Linux 额外要求：**
1. 确保安装必要软件包：
```
sudo apt update
sudo apt install gcc-11 g++-11 cpp-11
```
参阅 [详细说明](https://gcc.gnu.org/projects/cxx-status.html#cxx17)。

2. 配置 CUDA 环境：
```
export LD_LIBRARY_PATH=$LD_LIBRARY_PATH:/usr/local/cuda/lib64
```
参阅 [详细说明](https://docs.nvidia.com/cuda/cuda-installation-guide-linux/index.html#post-installation-actions)。

<Callout type="info">
确保 (V)RAM 可访问，使用虚拟内存的用户可能需要额外配置。
</Callout>

### 步骤 2：启用 GPU 加速

Jan 会自动管理 GPU 使用：
- 检测到支持时自动切换至 GPU 模式
- 自动选择 VRAM 最高的 GPU

验证 GPU 加速是否启用：
1. 打开 **设置** > **硬件**
2. 确认 **GPU 加速** 已开启
3. 在 Jan 底部 **系统监视器** 中确认所选 GPU 可见

<br/>
![硬件](./_assets/trouble-shooting-01.png)
<br/>

### 步骤 3：GPU 设置检查

1. 进入 **设置** > **通用** > **数据文件夹**
2. 点击 **打开所在文件夹**
3. 打开 `settings.json` 文件

示例 `settings.json`：

```
{
  "notify": true,
  "run_mode": "gpu",
  "nvidia_driver": {
    "exist": true,
    "version": "531.18"
  },
  "cuda": {
    "exist": true,
    "version": "12"
  },
  "gpus": [
    {
      "id": "0",
      "vram": "12282"
    },
    {
      "id": "1",
      "vram": "6144"
    },
    {
      "id": "2",
      "vram": "6144"
    }
  ],
  "gpu_highest_vram": "0"
}
```
**关键配置项说明：**
- `run_mode`：GPU 加速时应显示为 "gpu"
- `nvidia_driver`：显示驱动状态与版本
- `cuda`：显示 CUDA 工具包状态与版本
- `gpus`：列出可用 GPU 及其 VRAM（单位 MB）
- `gpu_highest_vram`：VRAM 最高的 GPU ID

### 步骤 4：重启 Jan

重启 Jan 以确保配置生效。

</Steps>

## 权限拒绝

运行 Jan 时可能遇到以下错误信息：

```
Uncaught (in promise) Error: Error invoking layout-480796bff433a3a3.js:538 remote method 'installExtension':
Error Package /Applications/Jan.app/Contents/Resources/app.asar.unpacked/pre-install/janhq-assistant-extension-1.0.0.tgz does not contain a valid manifest:
Error EACCES: permission denied, mkdtemp '/Users/username/.npm/_cacache/tmp/ueCMn4'
```

该错误通常由安装过程中的权限问题导致，请按以下步骤解决：

1. 打开您的**终端**

2. 执行以下命令将 `~/.npm` 目录所有权更改为当前用户：

```bash
sudo chown -R $(whoami) ~/.npm
```

该命令确保 Jan 安装时获得必要的权限。

## "获取失败"或"出现异常"错误

当您启动与模型的聊天并遇到**获取失败**或**出现异常**错误时，以下是可能的解决方案：

**1. 检查系统与硬件要求**

- 硬件依赖：确保设备满足所有[硬件要求](docs/troubleshooting#step-1-verify-hardware-and-system-requirements)
- 操作系统：确保符合最低要求（[Mac](/docs/desktop/mac#minimum-requirements)、[Windows](/docs/desktop/windows#compatibility)、[Linux](docs/desktop/linux#compatibility)）
- 内存：选择占用可用内存低于80%的模型
  - 8GB系统：使用6GB以下模型
  - 16GB系统：使用13GB以下模型

**2. 检查模型参数**

- 在右侧边栏的**引擎设置**中，检查`ngl`（[GPU层数](/docs/models/model-parameters#engine-parameters)）设置是否过高
- 从较低NGL值开始，根据GPU内存逐步增加

**3. 端口冲突**

如果查看[应用日志](/docs/troubleshooting#how-to-get-error-logs)发现"无法绑定地址127.0.0.1:39291"，请检查端口可用性：

```
# Mac
netstat -an | grep 39291

# Windows
netstat -ano | find "39291"
tasklist /fi "PID eq 39291"

# Linux
netstat -anpe | grep "39291"
```

<Callout type="info">
  `Netstat`会显示活动连接中各种网络相关数据结构的内容。
</Callout>

Jan 默认端口：

- Jan 和 Cortex API 服务器：`1337`
- Jan 文档服务：`3001`

**4. 恢复出厂设置**

执行恢复出厂设置可将 Jan 还原至初始状态，解决持续性问题。此操作将移除所有自定义设置、已下载模型及聊天记录。

1. 进入 **设置** > **高级设置**
2. 在 **恢复出厂设置** 处点击 **重置**

<Callout type="warning">
此操作将删除所有聊天记录、模型及设置。
</Callout>

**5. 尝试全新安装**

- 卸载 Jan 并清理数据目录（[Mac](/docs/desktop/mac#uninstall-jan)、[Windows](/docs/desktop/windows#uninstall-jan)、[Linux](docs/desktop/linux#uninstall-jan)）
- 安装最新[稳定版本](/download)

<Callout type="warning">
此操作将清除所有 Jan 数据。
</Callout>

## OpenAI 意外令牌问题

"Unexpected token"错误通常与 OpenAI API 认证或区域限制有关。

**步骤1：API 密钥配置**

1. 从 [OpenAI 开发者平台](https://platform.openai.com/) 获取有效 API 密钥
2. 确保密钥有足够余额及适当权限

**步骤2：区域访问**

1. 若您所在区域受限，请使用支持区域的 VPN 服务
2. 确认网络可连通 OpenAI API 端点
