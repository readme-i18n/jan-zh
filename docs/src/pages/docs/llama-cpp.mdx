# 本地 AI 引擎 (llama.cpp)

## 什么是 llama.cpp？

llama.cpp 是在您计算机本地运行 AI 模型的引擎。可以将其视为使 AI 模型文件在您的硬件（无论是 CPU、显卡还是 Apple M 系列芯片）上实际运行的软件。

该项目最初由 Georgi Gerganov 创建，旨在无需专用 AI 加速器或云端连接的情况下，高效地在消费级硬件上运行大语言模型。

## 为何重要

**隐私性**：您的对话内容永远不会离开本地设备
**成本**：无需支付月费或 API 调用费用
**速度**：模型下载后无需联网即可运行
**控制权**：自由选择运行哪些模型及其行为方式

## 引擎管理

| 功能 | 作用 | 使用场景 |
|---------|-------------|------------------|
| **引擎版本** | 显示当前运行的 llama.cpp 版本 | 检查与新模型的兼容性 |
| **检查更新** | 下载新版引擎 | 当新模型需要更新引擎时 |
| **后端选择** | 选择针对硬件优化的版本 | 安装新显卡或性能不佳时 |
| **自动更新引擎** | 自动将 llama.cpp 更新至最新版本 | 需要自动兼容新模型时启用 |
| **自动卸载旧模型** | 释放未使用模型占用的内存 | 运行多个模型或内存不足时启用 |

## 硬件后端

Jan 提供针对特定硬件优化的不同后端版本。可以将其视为不同的"驱动程序"——每个版本都针对特定处理器或显卡进行了调优。

<Callout type="warning">
使用错误的后端可能导致模型运行缓慢或加载失败。请选择与硬件匹配的版本。
</Callout>

## 性能设置

这些设置控制模型运行效率：

| 设置项 | 功能说明 | 推荐值 | 影响范围 |
|---------|-------------|------------------|---------|
| **连续批处理** | 同时处理多个请求 | 启用 | 使用多工具或多会话时速度更快 |
| **线程数** | 生成线程数量 | -1 (自动) | -1 表示使用所有逻辑核心，可按需调整 |
| **批处理线程数** | 批量及提示处理的线程数 | -1 (自动) | 通常与线程数设置相同 |
| **批量大小** | 逻辑最大批量尺寸 | 2048 | 数值越高并行处理能力越强 |
| **物理批量大小** | 物理最大批量尺寸 | 512 | 控制批处理时的内存使用量 |
| **GPU分配模式** | 模型在GPU间的分配方式 | 分层 | 多GPU配置最常用分层模式 |
| **主GPU索引** | 主要处理GPU | 0 | 需要更换主GPU时可调整此值 |

## 内存设置

这些选项控制模型如何使用计算机内存：

| 设置项 | 功能说明 | 推荐值 | 调整场景 |
|---------|-------------|------------------|----------------|
| **Flash Attention** | 提升内存使用效率 | 启用 | 除非出现问题否则保持启用 |
| **Disable mmap** | 禁用模型文件内存映射 | 禁用 | 遇到崩溃或页面置换问题时启用 |
| **MLock** | 将模型锁定在内存中，防止交换 | 禁用 | 内存充足且需要稳定性能时启用 |
| **Context Shift** | 处理超长对话上下文 | 禁用 | 超长对话或多工具调用时启用 |
| **Disable KV Offload** | 将KV缓存保留在CPU | 禁用 | GPU内存不足时启用 |
| **KV Cache K Type** | 键向量的内存精度 | f16 | 内存不足时可改为q8_0或q4_0 |
| **KV Cache V Type** | 值向量的内存精度 | f16 | 内存不足时可改为q8_0或q4_0 |
| **KV Cache Defragmentation** | 缓存清理阈值 | 0.1 | 数值越小碎片整理越频繁 |

### KV缓存类型详解

- **f16**: 16位全精度，占用内存多但质量最高
- **q8_0**: 8位量化，内存占用与质量平衡
- **q4_0**: 4位量化，内存占用最少，质量略有损失

## 高级设置

这些设置用于模型行为微调和高级用例：

### 文本生成控制

| 设置项 | 功能说明 | 默认值 | 调整时机 |
|---------|-------------|---------------|----------------|
| **最大预测标记数** | 生成的最大标记数量 | -1 (无限) | 需限制生成长度时设置 |
| **自定义Jinja聊天模板** | 覆盖模型的聊天格式 | 空 | 仅当模型需要特殊格式时 |

### RoPE (旋转位置编码) 设置

| 设置项 | 功能说明 | 默认值 | 调整时机 |
|---------|-------------|---------------|----------------|
| **RoPE缩放方法** | 上下文扩展方法 | 无 | 支持扩展上下文的模型使用 |
| **RoPE缩放因子** | 上下文缩放乘数 | 1 | 需要更长上下文时增加 |
| **RoPE基础频率** | RoPE的基础频率 | 0 (自动) | 通常从模型加载 |
| **RoPE频率缩放因子** | 频率缩放系数 | 1 | 仅限高级调优 |

### Mirostat采样

| 设置项 | 功能说明 | 默认值 | 调整时机 |
|---------|-------------|---------------|----------------|
| **Mirostat模式** | 替代采样方法 | 禁用 | 选择V1或V2可获得更稳定输出 |
| **Mirostat学习率** | 适应速度 | 0.1 | 需要更稳定输出时降低 |
| **Mirostat目标熵值** | 目标困惑度 | 5 | 需要更多变化时提高 |

### 输出约束

| 设置项 | 功能说明 | 默认值 | 调整时机 |
|---------|-------------|---------------|----------------|
| **语法文件** | 约束输出格式 | 空 | 需要结构化输出时(JSON、代码等) |
| **JSON模式文件** | 强制JSON结构 | 空 | 需要特定JSON格式时 |

## 常见问题排查

**模型无法加载:**

- 尝试切换后端(从CUDA切换到CPU或反之)
- 检查RAM/VRAM是否充足
- 更新至最新引擎版本

**性能极慢:**

- 确保启用GPU加速(CUDA/Metal/Vulkan后端)
- 增加模型设置中的GPU层数
- 关闭其他内存密集型程序

**内存不足错误:**

- 减少模型设置中的上下文长度
- 将KV缓存类型切换为q8_0或q4_0
- 尝试更小的模型变体

**随机崩溃:**

- 切换至更稳定的后端(尝试用avx替代avx2)
- 禁用超频设置(如已启用)
- 更新显卡驱动

## 快速设置指南

**多数用户建议:**

1. 使用Jan安装的默认后端
2. 启用引擎自动更新以保持兼容性
3. 保持所有性能设置为默认值
4. 仅在遇到问题时调整

**NVIDIA显卡用户:**

1. 从下拉菜单中选择合适的 CUDA 后端（例如 `avx2-cuda-12-0`）
2. 确保模型设置中的 GPU 层数调高
3. 保持 Flash Attention 启用状态
4. 若有多块 GPU，请设置主 GPU 索引

**若模型运行过慢：**

1. 检查是否启用了 GPU 加速（CUDA/Metal/Vulkan 后端）
2. 开启连续批处理
3. 增加批处理大小和微批处理大小
4. 关闭其他占用内存的应用程序

**若出现内存不足：**

1. 启用自动卸载旧模型功能
2. 将 KV 缓存 K/V 类型改为 q8_0 或 q4_0
3. 在模型设置中减小上下文长度
4. 若内存充足可启用 MLock
5. 尝试更小规模的模型

**高级用户建议：**

1. 尝试 Mirostat 采样以获得更稳定的输出
2. 使用语法/JSON 模式文件实现结构化生成
3. 针对支持扩展上下文的模型调整 RoPE 设置
4. 根据 CPU 性能微调线程数

<Callout type="info">
大多数用户无需修改这些设置即可成功运行 Jan。默认值已针对典型硬件配置进行了优化。
</Callout>
